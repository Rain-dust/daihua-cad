# 可编辑 DWG 分层交付验收

用于新建或修订的可编辑 DWG。以下约定主要适用于新建图或已明确授权的全图整理；用户对格式、图层标准、保留参照、打开方式和交付清单的明确要求优先。局部修订只对新增/修改对象与受影响内容验收和修正；保留原图无关图层、布局、动态块、属性、外参、字体与非 ByLayer 样式，已有问题只记录，不为通过全图检查器擅自整改。

## 绘制前确定语义图层

按实际构件、专业、用途分层。建筑装修图至少区分实际存在的墙、门、窗、楼梯、吊顶轮廓、灯槽、各类灯具、检修口、材料铺装、文字与尺寸；不同铺装材料应能分别选择和关闭。图框、布局文字和视口另设图层。图层名称及色号服从项目标准；ACI 色区分用于模型编辑，黑白打印通过 CTB/STB 控制。

新建或本次授权整理的图层必须有正确归属的实体，不能只创建空图层。明确要求全图重分层时依据构件语义整理所用底图；仅局部修改时沿用原图结构，不为统一门窗、踏步和墙体的分层改动无关内容。

## 保留 CAD 编辑语义

- 设计主体必须是原生可编辑实体。不得将整张 PDF/图片、PDF 导入碎线或整图单一块作为可编辑 DWG 的替代交付；经明确要求的参照底图可保留，但应单独命名分层，并与设计实体区别。
- 新建模型实体颜色、线型、线宽通常设为 ByLayer，顶层对象使用语义图层，0 层可用于块定义内部；沿用客户模板或局部修改时服从既有标准，不强改无关对象。不要通过硬编码颜色将整个模型做成黑白打印稿。
- 尺寸使用 DIMENSION，文字使用 TEXT/MTEXT；不要炸开尺寸或将文字转为线段。门扇开启线保留 ARC，曲线保留适合的原生曲线实体。
- 规则铺装和板材分格优先使用可修改参数的 HATCH，按材料与房间分区，关联有效闭合边界；避免用大量碎线模拟可编辑填充。确需独立排版线时，应保留连续图元、材料语义图层及可追溯排版基准。
- 重复灯具等组件使用有名称的 INSERT，按组件类型分层；块内的 0 层 ByLayer/ByBlock 属正常用法。不得把整张图打包为一个难以分层编辑的块。
- 新建模型按实际单位与 1:1 建立；按所需形式设置图框和打印布局。模型空间需要带框时，仅按出图关系安排图框，不缩放设计几何。新建编辑图可保存到模型空间并保留打印布局；既有图纸局部修改保留原单位、空间和布局设置。

## 打开状态与模型背景

新建且用于继续编辑的图纸可默认保存模型空间完整视图；已有图纸保留原打开空间、视图和布局，除非任务要求调整。

- 新建编辑图保存前可回到模型空间（TILEMODE=1）设置完整视图；不因此切换既有图纸的交付空间。用户要求带图框时，确认交付 DWG 中确有图框/图签实体或块，默认模型编辑视图也能看到所需图框；不能只在 PDF 里补框。
- 语义图层使用可辨识的颜色，模型背景沿用使用者设置，打印黑白由 CTB/STB 控制。不得为做出纸张外观而添加覆盖整幅的 SOLID/HATCH、WIPEOUT、图片或 OLE 底板；有实际遮挡用途的小范围遮罩可按需保留。
- 若打开后全白，先分辨是停在纸空间、存在整幅白底对象，还是应用的模型背景设置；针对原因修正。正常 PDF/打印布局的白纸不需要改成黑底。
- 背景色属于 CAD 应用配置，不是 DWG 可保证跨电脑携带的属性。仅在当前使用者要求时调整应用背景；不得用新增底色填充伪造界面，也不得将改背景当作原生对象/分层验收通过。
- 每张保存后的 DWG 均回读检查，核对约定或应保留的空间、视图与布局；对每类图纸抽查实际 CAD 编辑界面和图层隔离，不能用 PDF 渲染截图替代。涉及图层隔离、改尺寸或填充的测试在临时副本进行，结束后恢复正常图层状态。

## 必须检查保存后的 DWG

原生 AUDIT 的 0 错误只说明数据库结构可读，不等于图层/编辑语义合格。每张交付 DWG 都要重新打开，通过 CAD API 查询，或由 CAD 原生导出 DXF 后检查：

1. 按“空间、图层、实体类型”清点，核对本次对象的归属和编辑性。新建图检查 0/Defpoints 混放及未声明的图片、PDF 底图、OLE 或代理主体；既有图局部修改保留原结构，不能因这些原有内容擅自重画或移除。
2. 核对任务对象样式及应保留的层颜色/线宽、模型单位和尺寸、布局比例；不能仅检查扩展名、总实体数、图层名存在或渲染图片。
3. 核对原生 DIMENSION、HATCH、INSERT、TEXT/MTEXT 等与图纸用途匹配。检查 HATCH 关联句柄指向有效闭合边界。
4. 对每种图纸类型抽查图层关闭/隔离，确认仅影响对应构件；在临时副本上修改一个填充参数或关联边界、一个组件或尺寸，确认可编辑且显示更新，不改交付原件。
5. 比较 PDF/打印预览和模型内容，核对同一版图形、图框和文字。图层对照表、核验数据与截图仅存内部工作目录，不自动附入客户交付文件夹。任何一项不符先修正，禁止仅凭工具 success 或 AUDIT 0 宣布合格。

新建图或授权全图整理时，可用 [audit_editable_dxf.py](../scripts/audit_editable_dxf.py) 检查原生回读 DXF。它执行全图严格检查，局部修改不应为了消除原图已有报告项扩大整改；改用目标对象断言及修改前后对比检查保留内容，不将全图 passed 作为局部修订硬门槛：

```text
python audit_editable_dxf.py saved_dwg_readback.dxf --manifest expected.json --output layer_audit.json
```

manifest 用文件 stem 作键，值可包含 required_layers（层名到最少对象数）、required_types（原生类型到最少数量）、layer_types（层名到允许类型列表）、require_associative_hatches、open_in_modelspace、viewport_scale、reject_whole_drawing_block。这些断言应来自图纸需求，不应直接复制待验收文件的统计结果。脚本是静态检查，不能替代构件分类和关闭图层后的视觉核对。

## 简短命名与客户交付目录

- 未指定时，对外文件夹使用一个能识别项目的简短名称，避免把制作过程写进目录名。用户已指定名称或版本规则时沿用；内部版本和备份另存。
- 图纸文件使用简短图号和正式图名，例如“01_总平面图.dwg”“01_总平面图.pdf”；同张两种格式保持同名。多图合订 PDF 需要时用“图纸.pdf”等短名。
- 客户文件夹从新的空目录或明确挑选的最终文件构建，只包含客户约定的最终格式和文件；DWG、DXF、PDF、源代码等均按项目清单交付，不因本参考文档擅自增加格式。最终图纸齐全，需要 PDF 时与 CAD 同版；不把中间候选版本一并装入。
- 中间 DXF、核验数据、日志、截图、预览、脚本、临时 PDF、.bak/.sv$/.dwl/.dwl2 等默认放在独立工作目录。用户要求交付其中某类成果时纳入清单；不要混入未请求的中间版本。
- 保留并核对原图必要的外参、字体等依赖。按约定打包依赖或处理路径；绑定外参、替换字体会改变结构或显示，须有任务依据并检查影响，不作为自动整理步骤。不能为满足扩展名清单删掉必要依赖后交付残缺 DWG。
- 第三方来源和制作记录默认仅留内部工作记录；如实际使用素材的许可证要求随成果附带声明，优先选择无需额外文件的素材或许可证允许的图内声明方式，不能静默删除必须保留的声明。
- 需要 ZIP 时，用同一核心主题命名，置于客户文件夹旁边；从干净客户文件夹打包，不从整个工作目录递归打包。最终答复优先给客户文件夹/ZIP 和 PDF，不把内部记录当作默认交付链接。

交付前递归检查文件夹与 ZIP 的成员：仅有项目清单中预期的最终成果，数量与当前图纸清单一致，没有未请求的隐藏文件、内部子目录、旧版、备份或临时文件。发现多余内容时重新从明确清单构建干净目录，不盲目删除混有用户文件的既有目录。
